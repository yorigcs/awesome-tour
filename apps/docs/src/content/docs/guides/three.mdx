`@awesome-tour/three` lets steps target **objects inside a WebGL scene**. The object's bounding box
is projected to the screen on demand, so the regular DOM overlay and card follow it as the camera
moves — no special UI needed.

```bash
pnpm add @awesome-tour/three   # peers: @react-three/fiber, three
```

```tsx
import { anchor, createTour } from '@awesome-tour/react';
import { TourTarget3D, useTourCamera } from '@awesome-tour/three';
import { Canvas } from '@react-three/fiber';

const tour = createTour({
  id: 'lw-16',
  steps: [
    { id: 'pads', target: anchor('pads'), title: 'Sixteen pads' },
    { id: 'knobs', target: anchor('knobs'), title: 'Hands-on knobs' },
  ],
});

function CameraRig() {
  useTourCamera({
    pads: { position: [-0.5, 3.1, 3.1], lookAt: [-0.5, 0, -0.1] },
    knobs: { position: [1.5, 2.1, 2.9], lookAt: [0.9, 0, 0.2] },
  });
  return null;
}

export function Showroom() {
  return (
    <Tour.Root tour={tour}>
      <Canvas>
        <TourTarget3D name="pads">
          <Pads />
        </TourTarget3D>
        <TourTarget3D name="knobs">
          <Knobs />
        </TourTarget3D>
        <CameraRig />
      </Canvas>
      <TourCard /> {/* your usual Tour.Portal / Tour.Content */}
    </Tour.Root>
  );
}
```

- `TourTarget3D` registers an [anchor](../targets/#anchors) whose rect is the projected bounding box
  of its children (or of the `object` ref you pass).
- `useTourCamera(shots)` eases the camera to the shot of the current step. Pass
  `{ controls }` to keep orbit controls in sync, and `smoothing` to change the speed.
- `projectObjectToRect(object, camera, canvas)` is exported for custom setups.

Because a 3D target is a [virtual element](../targets/#virtual-elements), the same approach works for
any canvas: maps, charts, editors.

Full API in the [three reference](../../reference/three/).
