A tour with `rules` decides by itself whether it should appear. The
[tour manager](../multiple-tours/) (the one inside `TourProvider`) evaluates them, starts tours
when their trigger fires, and remembers impressions — how often each tour was shown, how it ended,
when it was snoozed.

## Rules

```ts
const tour = createTour({
  id: 'billing-tips',
  steps,
  rules: {
    audience: ({ data }) => data.plan === 'pro',                 // targeting
    schedule: { startsAt: '2026-12-01', endsAt: '2027-01-15' },   // a dated campaign
    frequency: { once: true, maxShows: 3, cooldownMs: 86_400_000 },
    trigger: { route: '/billing/*' },                             // start by itself
    priority: 10,
  },
});
```

| Rule        | Passes when                                                                         |
| ----------- | ----------------------------------------------------------------------------------- |
| `audience`  | `audience({ data })` returns true (may be async — fetch a feature flag here).        |
| `schedule`  | Now is between `startsAt` and `endsAt` (`Date`, ISO string or timestamp).            |
| `once`      | `true` (default): never completed, skipped or dismissed. `'completed'`: never completed or skipped — closing it with <kbd>Esc</kbd> isn't final. `'seen'`: never shown. `false`: off. |
| `dismissCooldownMs` | After a dismissal (close, <kbd>Esc</kbd>), at least this long has passed. Pairs with `once: 'completed'`. |
| `maxShows`  | It was shown fewer than `maxShows` times.                                            |
| `cooldown`  | At least `cooldownMs` passed since it was last shown.                                |
| `snooze`    | Any `tour.snooze(ms)` has expired.                                                   |

<Aside>
  Rules gate **automatic** starts — triggers and `manager.startIfEligible(id)`. An explicit
  `start()` (a "Take the tour" button, `Tour.Trigger`) always works: the user asked for it.
</Aside>

## Triggers

`trigger` starts the tour by itself, when it's eligible and **no other tour is on screen** (a
triggered tour never interrupts or queues behind another one — it gets its chance next time).

| Trigger         | Fires when                                                                 |
| --------------- | -------------------------------------------------------------------------- |
| `route`         | The router reaches a matching path (`/projects/:id`, `/docs/*`).           |
| `signal`        | Your app calls `manager.signal(name)` — after a feature is used, a plan changes… |
| `event`         | A DOM event happens on (or inside) a target: `{ type: 'click', target: '#help' }`. |
| `delay`         | This many ms after the tour is registered.                                 |
| `targetVisible` | A target appears on the page.                                              |
| `dwell`         | The pointer rests on (or focus stays in) a target for `ms` (default 2000): `{ target: '#mixer', ms: 1500 }`. |
| `idle`          | No pointer, key, wheel or scroll activity for this many ms.                |
| `rageClick`     | `clicks` (3) fast clicks within `within` ms (800) on one element, optionally inside `target`. |
| `repeat`        | `manager.signal(signal)` happened `times` times (2), optionally `within` ms: the same error twice. |

A **first visit** to a page is `trigger: { route }` with the default `once`.

## Snooze

`tour.snooze(ms)` closes the tour and keeps it from auto-starting until the time is up — the
"Remind me tomorrow" button:

```tsx
function RemindLater() {
  const { tour } = useTour();
  return <button onClick={() => tour.snooze(24 * 60 * 60 * 1000)}>Remind me tomorrow</button>;
}
```

## Across tours

Rules are per tour; users experience all of them together. A manager-wide **cap** keeps automatic
tours, announcements and surveys from piling up:

```ts
const manager = createTourManager({
  tours,
  cap: { perSession: 1, cooldownMs: 24 * 60 * 60_000 }, // one a session, a day apart
});
```

When a tour's content changes, `frequency.perVersion` makes it eligible again for people who
finished an older `version` — release notes that come back for each release:

```ts
createTour({ id: 'whats-new', version: 24, rules: { frequency: { once: true, perVersion: true } }, steps });
```

## Remembering impressions

By default impressions live in memory (lost on reload). Give the provider any
[persistence adapter](../../reference/persistence/) to keep them — in the browser or on your server:

```tsx
import { localStorageAdapter, TourProvider } from '@awesome-tour/react';

const impressions = localStorageAdapter({ prefix: 'tour-impressions:' });

<TourProvider tours={tours} router={router} impressions={impressions}>…</TourProvider>;
```

## Why didn't my tour show?

`manager.explain(id)` returns every rule's verdict with a reason:

```ts
const report = await manager.explain('billing-tips');
// { eligible: false, checks: [
//   { rule: 'audience', ok: false, detail: 'audience() returned false' },
//   { rule: 'once', ok: true, detail: 'not finished yet' },
// ] }
```

The [devtools](../devtools/) **Rules** tab shows the same report for every tour, live, with
buttons to start a tour if eligible and reset impressions.
