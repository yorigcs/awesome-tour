## What you get

- **Tours** — every tour registered on the `TourProvider` (plus any passed in `tours`), with status,
  phase, version and progress. Buttons to restart, go back and forth, pause, resume, complete and
  close.
- **Steps** — each step's target health: _centered_, _found_, _missing_, _on /route_ (lives on
  another page) or _hidden_ (`when` is false). Hover a step to highlight its target on the page;
  click it to jump there (navigating if needed).
- **Data** — the tour's `data` and its last error.
- **Events** — a live timeline of every tour event.
- **Checklists** — progress per checklist; click an item to toggle it.

Toggle the panel with <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>T</kbd> (`shortcut` prop, `false` to
disable). It renders inside a shadow root, so your CSS and its CSS never mix (`isolate={false}` to
opt out), and it remembers whether it was open.

### Rules

The **Rules** tab answers "why didn't my tour show?": for every tour on the provider it lists each
[display rule](../display-rules/) — audience, schedule, once, max shows, cooldown, snooze — with
whether it passes and why, plus buttons to start a tour if eligible and to reset impressions.

### Element picker

**Pick element**, then click anything on the page: devtools suggests the most stable way to target
it — an existing `anchor()`, a `data-tour` / `data-testid`, a meaningful `id` or accessible name,
and only then a structural path — and gives you a step snippet to copy. Picking never triggers the
element (links don't navigate, buttons don't fire). <kbd>Esc</kbd> cancels.

### Export

**Export JSON** downloads a snapshot of every tour's state, the manager's queue and the event log —
attach it to a bug report.

## Funnel

The **Funnel** tab counts this session's runs of each tour: how many reached each step, where they
dropped off, how they ended, and how many reached the tour's [goal](../analytics/#goals). Click
through a tour a few times, closing it at different steps, and you see the drop-off before any
analytics is wired up.

## Recorder

The **Record** tab builds a tour by clicking through your app:

1. **+ Element**, then click the thing the step should point at. The picker keeps the most stable
   target it can find (`anchor`, `byTour`, `byRole` and name, then an id or selector) and the page
   you were on. Navigate between picks as you like; the recording survives reloads.
2. Type a title and description, pick a side, reorder or remove steps. **+ Centered** adds a step
   without a target.
3. **Play** runs it right away, as a [preview](../json-tours/#previewing-drafts) (nothing saved or
   tracked).
4. **Copy JSON** for your CMS, or **Copy code** for a `createTour` call — routes are written where
   the page changes.

Then put the result through the [health check](../testing/#tour-health-checks) in CI.

## Usable during modal tours

The panel carries the `data-tour-keep` attribute: modal tours don't make it `inert`, and tour
keyboard shortcuts ignore keys pressed inside it. Use the same attribute for your own toasts or
support widgets.

## Keep it out of production

Render it behind a development check so bundlers drop it:

```tsx
{process.env.NODE_ENV !== 'production' && <TourDevtools />}
```

Or lazy-load it only for internal users:

```tsx
const TourDevtools = lazy(() =>
  import('@awesome-tour/devtools').then((m) => ({ default: m.TourDevtools })),
);
```

Full API in the [devtools reference](../../reference/devtools/).
