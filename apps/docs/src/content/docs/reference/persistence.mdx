```ts
import { createTour, localStorageAdapter, persist } from '@awesome-tour/core';

const onboarding = createTour({
  id: 'onboarding',
  version: 3,
  steps,
  plugins: [persist(localStorageAdapter(), { persistData: true })],
});
```

## persist(adapter, options?)

A [plugin](../plugins/) that writes `{ status, stepId, version }` to the adapter whenever the status or step changes, and reads it back in `beforeStart`.

| Option        | Type                         | Default        | Description                                                                                                         |
| ------------- | ---------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------- |
| `key`         | `(tourId: string) => string` | `(id) => id`   | Storage key for a tour (the adapter may add its own prefix).                                                        |
| `resume`      | `boolean`                    | `true`         | Start again from the last saved step.                                                                               |
| `once`        | `boolean`                    | `true`         | Don't start tours saved as `completed` or `skipped`. `start({ force: true })` / `restart()` still work.             |
| `persistData` | `boolean`                    | `false`        | Also save `tour.data` (on every change) and restore it on start.                                                    |
| `sync`        | `boolean`                    | `true`         | When the adapter supports `subscribe`: if the tour is completed or skipped elsewhere (another tab), finish it here too. |
| `migrate`     | `Record<number, (saved) => PersistedTourState \| null>` | — | Upgrade progress saved by an older `version` instead of dropping it. `migrate[v]` turns a `v` state into a `v + 1` one; steps chain up to the current version. |

### What happens on `start()`

1. The saved value is read (`adapter.get(key)`). Nothing saved → normal start.
2. Saved `version` differs from `tour.version` → it's upgraded through `migrate` (and saved back); without a path to the current version, the entry is removed and the tour starts fresh.
3. `force: true` → normal start (saved progress ignored).
4. `once` and the saved status is `completed` / `skipped` → the start is blocked (status stays as it was).
5. Otherwise the tour resumes at the saved `stepId` (if `resume`) with the saved `data` (if `persistData`).

States `active`, `paused`, `closed`, `completed` and `skipped` are written; `idle` and `starting` are not.

<Aside>
Bump the tour's `version` when you change its steps meaningfully: everyone sees the new tour once, even if they finished the old one.
</Aside>

## PersistedTourState

| Field       | Type             | Description                           |
| ----------- | ---------------- | ------------------------------------- |
| `status`    | `TourStatus`     | Last status.                          |
| `stepId`    | `string \| null` | Last step.                            |
| `version`   | `number`         | `tour.version` when saved.            |
| `data`      | `unknown`        | Only with `persistData`.              |
| `updatedAt` | `number`         | `Date.now()` when saved.              |

## Adapters

### PersistenceAdapter

Any object with this shape — sync or async — works. It's generic, so checklists reuse it (`PersistenceAdapter<ChecklistSnapshot>`).

```ts
interface PersistenceAdapter<T = PersistedTourState> {
  get(key: string): T | null | undefined | Promise<T | null | undefined>;
  set(key: string, value: T): void | Promise<void>;
  remove(key: string): void | Promise<void>;
  /** Optional: notify about changes made elsewhere (other tabs, server push). */
  subscribe?(key: string, listener: (value: T | null) => void): () => void;
}
```

### localStorageAdapter(options?)

Stores JSON in `localStorage` under `prefix + key`, and implements `subscribe` with the `storage` event (cross-tab sync). Fails silently when storage is unavailable (SSR, privacy mode, quota).

| Option   | Type     | Default            |
| -------- | -------- | ------------------ |
| `prefix` | `string` | `'awesome-tour:'`  |

```ts
persist(adapter, {
  migrate: {
    // v1 → v2: the "upload" step was renamed "import".
    1: (saved) => ({ ...saved, stepId: saved.stepId === 'upload' ? 'import' : saved.stepId }),
  },
});
```

### sessionStorageAdapter(options?)

Like `localStorageAdapter`, but progress lives as long as the browser tab (no cross-tab sync).

### memoryStorage()

In-memory `Map`. Progress is lost on reload — handy in tests and for "per session" tours.

### httpAdapter(options)

Progress that follows the user across devices, through your API: `GET`, `PUT` and `DELETE` on
`${url}/${key}` (a `GET` answering 404 means "nothing saved").

```ts
import { httpAdapter, persist } from '@awesome-tour/react';

const server = httpAdapter({
  url: '/api/tour-progress',
  headers: async () => ({ authorization: `Bearer ${await getToken()}` }),
});

createTour({ id: 'onboarding', steps, plugins: [persist(server, { key: (id) => `${userId}:${id}` })] });
```

| Option     | Type                                         | Default        | Description                                    |
| ---------- | -------------------------------------------- | -------------- | ---------------------------------------------- |
| `url`      | `string`                                     | —              | Base URL; the key is appended.                 |
| `headers`  | `HeadersInit \| () => HeadersInit \| Promise` | —              | Sent with every request.                       |
| `fetch`    | `typeof fetch`                               | global `fetch` | Custom fetch (tests, SSR, interceptors).       |
| `debounce` | `number`                                     | `300`          | Coalesce rapid writes per key (ms).            |

Reads hit the network once per key, then a cache. Writes are optimistic (cached immediately) and
debounced. Network failures behave like "nothing saved", so a flaky API never breaks the app.

Anything else — Supabase, Firebase, your own store — is a `PersistenceAdapter`: `get`, `set`,
`remove` (sync or async) and an optional `subscribe`.

## readTourProgress(adapter, tourId, options?)

Reads the saved state, e.g. to show a "Resume tour" button.

```ts
const saved = await readTourProgress(localStorageAdapter(), 'onboarding');
if (saved?.status === 'closed') showResumeButton();
```

If you gave `persist` a custom `key`, pass the same function:

```ts
const key = (id: string) => `${user.id}:${id}`;
persist(adapter, { key });
await readTourProgress(adapter, 'onboarding', { key });
```
